# 个人自用版界面规划

本文梳理 new-api 当前前端页面的完整清单，按"单人自建、自己用、不对外营业"的场景，区分哪些是必需的、哪些纯属冗余，并给出精简后的信息架构和移动端改造方向。

## 一、当前页面清单（现状）

### 公开页（无需登录）

| 页面 | 路由 | 个人版需要吗 |
|---|---|---|
| 落地页 Home | `/` | 不需要，纯对外宣传 |
| 模型价格 Pricing | `/pricing` | 不需要公开版，并入后台模型页 |
| 排行榜 Rankings | `/rankings` | 不需要，多用户场景 |
| 关于 About | `/about` | 不需要 |
| 用户协议 / 隐私政策 | `/user-agreement`, `/privacy-policy` | 不需要 |
| 注册 / 找回密码 / OTP / OAuth 回调 | `/sign-up` 等 | 不需要（关闭注册后隐藏） |
| 初始化向导 Setup | `/setup` | 保留，装完跑一次 |

### 登录后页面

| 页面 | 内容 | 个人版需要吗 |
|---|---|---|
| 仪表盘 Dashboard | 概览 / 模型分析 / 流量 / 用户分析 四个分区 | 大幅简化后保留 |
| 渠道 Channels | 上游渠道增删改查、测活、标签 | 核心，保留 |
| 令牌 Keys | API Key 管理、分组、额度 | 核心，保留 |
| 使用日志 Usage Logs | 普通 / 绘图 / 任务 三类日志 | 核心，保留 |
| 模型 Models | 模型元数据 / 部署配置 | 简化后保留 |
| 钱包 Wallet | 余额、充值、支付记录 | 不需要，个人没有充值场景 |
| 兑换码 Redemption Codes | 生成、兑换、管理 | 不需要 |
| 订阅 Subscriptions | 订阅计划售卖 | 不需要 |
| 用户管理 Users | 用户增删改、分组、额度 | 不需要，只有一个人 |
| 个人中心 Profile | 账号、安全、Passkey、通知 | 保留 |
| Playground / 聊天 | 在线调试模型 | 可选保留 |
| 系统信息 System Info | 版本、环境 | 并入设置页 |
| 系统设置 System Settings | 站点 / 认证 / 计费 / 模型路由 / 安全限流 / 内容 / 运维，共 7 组几十个子页 | 压缩成 1 页 |
| 错误页 4xx/5xx | 401/403/404/500/503 | 保留 |

现状问题：整套界面是为"多人注册的付费中转站"设计的，商业化功能（钱包、兑换码、订阅、用户管理、排行榜）占了导航近一半；系统设置拆成 7 个分组、每组再套 `$section` 子路由，层级过深；移动端用抽屉硬套桌面端的多级导航，表格在窄屏上不可用。

## 二、个人版应该有的界面（目标）

总共 7 个界面，导航一层打平，手机上用底部标签栏：

1. **概览** — 今日调用次数、花费、余额；近 7 天用量曲线；最近报错的渠道。不要四分区仪表盘，一屏放完。
2. **渠道** — 上游渠道的列表、添加、测活、启停、优先级。这是个人版最复杂的页面，保持完整功能，移动端改为卡片列表。
3. **令牌** — 创建/删除 API Key，看每个 Key 的用量。去掉分组、兑换等面向外部用户的概念。
4. **日志** — 一张表看所有调用（模型、渠道、耗时、token、费用），支持按模型/状态筛选；绘图和任务日志并入同一列表，加类型筛选即可。
5. **模型** — 当前可用模型列表、每个模型的倍率/价格、启停。合并现在的"模型元数据"和公开 Pricing 页。
6. **设置** — 单页分区：基础信息（站点名、服务器地址）、登录安全（改密码、Passkey、两步验证）、通知（SMTP/Webhook）、限流、数据管理（备份/清理日志）。原来 7 组导航压成一个长页加锚点。
7. **调试（可选）** — 保留现有 Playground，用来快速验证渠道是否通。

登录保留最简版：一个账号密码登录页，可选 Passkey。注册、找回密码（改用命令行重置）、OAuth 绑定外部账号，个人版全部不需要。

## 三、直接砍掉的模块

- 钱包 / 充值 / 支付通道（`wallet`、billing 设置组）
- 兑换码 `redemption-codes`
- 订阅计划 `subscriptions`
- 用户管理 `users`（个人版后端可固定单用户模式）
- 排行榜 `rankings`
- 落地页、关于、法律条款页
- 系统设置中的"内容管理"（公告、文档、FAQ）和"站点品牌"的大部分
- Dashboard 的"用户分析"分区

砍掉的收益：前端路由从 60 多条降到 15 条以内；导航从两级分组变一层；移动端不再需要抽屉套抽屉。

## 四、移动端改造方向

- 导航改为底部标签栏（概览 / 渠道 / 令牌 / 日志 / 更多），不再用侧边抽屉承载多级菜单。
- 所有数据表格在窄屏下切换为卡片列表，渠道、令牌、日志三个列表是重灾区。
- 表格筛选改为底部弹层（bottom sheet），日期选择用原生控件。
- 表单页（添加渠道、添加令牌）改为全屏分步，不用桌面端的弹窗表单。
- 触控目标不小于 44px，去掉依赖 hover 的交互，行内操作改为左滑或长按菜单。

## 五、落地顺序建议

1. 先做信息架构：砍掉第三节列出的路由和导航项，后端已有"关闭注册"相关设置可以复用。
2. 渠道、令牌、日志三个核心页做移动端卡片化。
3. 设置页整合。
4. 概览页重做为单屏。
5. 最后处理视觉细节（配色、间距、暗色模式一致性）。
