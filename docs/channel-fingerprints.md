# 渠道指纹检测与模型端点（2026-09-20）

在渠道编辑页的“模型与分组”中开启“中转站检测”。保存后，测试渠道弹窗每个模型的测速按钮前会出现指纹按钮。当前支持 OpenAI 和 Anthropic 渠道。

点击指纹按钮即发起最多三次独立、计费的数字生成请求。结果显示参考库内相对得分排名、逐次排名、有效整数数量和原始回答。得分不是身份概率，未收录的模型也会接近某个候选；拒绝或请求错误不会被算作某个模型。只收集到部分有效回答时，汇总只使用有效回答，应结合逐次结果判断。

请求复用现有渠道测试的认证、模型映射、代理、参数覆盖、供应商转换和用量记录。前端不获取渠道密钥。指纹接口使用 ChannelOperate 权限，服务端再次检查渠道开关和模型归属；每实例每渠道只运行一次指纹任务，每次任务最多三次调用，每次70秒、总计4分钟。不自动重试或自动定时采集。

## 参考库

- Claude：2026-09-20 独立采集的 OpenRouter 七模型库（Fable 5/5.1、Sonnet 4.6、Opus 4.6/4.7/4.8/5），共94份参考回答，主评分模型使用其中64份共享环境样本。保留验证过的基准库，未采用改善不稳定的实验库。
- GPT：用户认可的 ModelTrace GitHub 原始库，采集来源声明为 Codex。保留原始统计空间，界面只返回六个 GPT 候选，不把该库的第三方 Claude 参考作为可信 Claude 输出。
- 当前按待测模型名称的 `gpt` 前缀选择 GPT 库，其余名称使用 Claude 库。两个参考空间的原始分数不能直接合并比较，结果页明确展示所用参考库。此版本不做跨家族身份结论，也不使用行为选择题或拒绝概率融合。
- 算法为平滑 Hellinger 特征、环境方向投影和有序块特征的0.75/0.25组合，移植自 ModelTrace。MIT 原文随代码保存在 `pkg/modelfingerprint/data/MODELTRACE-LICENSE`。
- Go 回归测试使用既有真实回答的 Python 评分快照比较完整排名与数值；不会在 CI 调用付费模型。

## 逐模型端点

OpenAI 渠道可为每个已选模型保存“自动”“Chat Completions”或“Responses”。设置以客户端模型名为键保存在渠道 setting JSON 的 model_endpoints 中，互不影响其他渠道。

- 自动：使用既有渠道/模型路由，以及全局 Chat→Responses 策略。
- Chat Completions：该模型的普通 Chat 请求不再受全局 Chat→Responses 转换策略影响。
- Responses：普通 Chat 请求、通过兼容转换处理的 Anthropic 请求自动转换到 Responses；已有 Responses 调用仍使用 Responses。渠道自动测速和指纹测试直接选择 Responses。
- 渠道测试中手工指定的端点优先于保存值；compact 保留专用行为。
- 端点偏好不是任意协议双向转换开关，例如不会把原生 Responses 请求强制降级为 Chat。Anthropic 渠道仍使用自己的供应商适配器，不显示 OpenAI 端点选择。
- 不支持同时开启渠道正文原样转发和端点偏好，后端拒绝这种冲突配置。明确的渠道端点偏好优先于全局正文转发开关，以保证所保存协议生效。

AICoding_OA 的两个 GPT 型号可以保存为 Responses，从而无需在测速弹窗逐次选择。配置不能修复上游自身超时或模型不可用。

## 验证与发布

用户要求不在 VPS 编译测试。Container Image 工作流先执行前端类型检查、相关前端回归和 Go 回归，再构建镜像及部署。测试过程中不使用服务器上的 API 凭据。
